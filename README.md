# Лабораторные работы по программированию на Java

Комплект рассчитан на первый семестр второго курса. 

Лекции и обязательная часть лабораторных одинаковы для направлений:

- 09.03.04 «Программная инженерия», профиль «Разработка и сопровождение программного обеспечения»;
- 09.03.01 «Информатика и вычислительная техника», профиль «Инженерия систем искусственного интеллекта».

Профильные варианты различаются только предметными данными. Конструкции Java, объем работы и критерии оценивания совпадают.

## Организация работы

Используются два типа репозиториев:

1. Центральный репозиторий курса — условия, справочники, объявления и FAQ. Студенты имеют доступ только на чтение.
2. Один приватный репозиторий студента на весь семестр — решения лабораторных работ.

В личном репозитории каждая лабораторная выполняется в отдельной ветке и сдается через pull request в `main` этого же репозитория. Обязательный CI в первом семестре не используется: студент запускает сборку и тесты локально через Maven Wrapper.

## Структура личного репозитория

```text
student-java/
├── .github/
│   └── pull_request_template.md
├── README.md
├── lab01/
│   ├── pom.xml
│   └── src/
│       ├── main/java/
│       └── test/java/
├── pom.xml
├── mvnw
├── mvnw.cmd
└── .gitignore
```

Репозиторий создается из подготовленного преподавателем шаблона. В текущей стартовой версии настроен модуль `lab01`: в нем есть пример метода `CourseToolkit.isEven` и два проходящих JUnit-теста. Намеренно падающих тестов в `main` нет.

Модули следующих работ не считаются частью текущей стартовой версии. Преподаватель публикует их каркасы до начала соответствующей работы либо заранее добавляет их в шаблон до создания личных репозиториев. Изменения template repository не появляются в уже созданных личных репозиториях автоматически.

## Процесс выполнения лабораторной

### 1. Обновить `main`

```bash
git switch main
git pull --ff-only origin main
```

### 2. Создать ветку

```bash
git switch -c lab/01-basics
```

Имена веток:

```text
lab/01-basics
lab/02-classes
lab/03-polymorphism
lab/04-object-contracts
lab/05-files
lab/06-generics
lab/07-streams
lab/08-concurrency
```

### 3. Выполнить подготовительную и обязательную части

Студент дома выполняет подготовительную часть, затем обязательное задание. Код и тесты обеих частей входят в одну ветку и один PR. Дополнительная часть выполняется после полного завершения обязательной.

### 4. Запустить локальную проверку

```bash
./mvnw -pl lab01 test
```

Для Windows:

```powershell
.\mvnw.cmd -pl lab01 test
```

### 5. Сделать commit и push

```bash
git status
git add lab01
git commit -m "Complete lab 01"
git push -u origin lab/01-basics
```

### 6. Создать pull request

На GitHub создается PR `lab/01-basics → main` с названием:

```text
[READY] ЛР 01 — Фамилия Имя
```

Шаблон описания:

```markdown
## Выполнено

- [x] подготовительная часть;
- [x] обязательная часть;
- [x] собственные тесты;
- [x] локально выполняется ./mvnw -pl lab01 test.

## Проверенные граничные случаи

- ...

## Основные решения

- ...

## Использование генеративного ИИ

Инструмент и цель использования либо «не использовался».

## Вопросы преподавателю

- ...
```

### 7. Проверка и защита

Преподаватель просматривает diff, публичные тесты и ключевую часть решения. На защите студент объясняет код и выполняет небольшое изменение без генеративного ИИ.

После замечаний заголовок меняется на `[FIX]`. После принятия преподаватель пишет итоговый комментарий `Принято`, студент меняет заголовок на `[ACCEPTED]` и самостоятельно сливает PR в `main`.

## Уровни задания

Каждая лабораторная содержит:

1. **Подготовительную часть** — небольшое обязательное упражнение, которое студент выполняет дома перед сдачей работы. Оно проверяет минимальные знания, необходимые для основной задачи.
2. **Обязательную часть** — проверяет одну основную тему и рассчитана на среднего студента.
3. **Дополнительную часть** — более сложные API, обобщение решения или исследовательская задача.

Дополнительная часть не компенсирует невыполненные требования обязательной.

На занятии преподаватель не проводит отдельный семинар по подготовительной части: проверяет результат, задает вопросы по решению и принимает защиту. Невыполненная подготовительная часть означает, что работа не готова к защите.

## Языковой бюджет

В каждой лабораторной указано, какие конструкции уже предполагаются изученными. Более сложный код не считается преимуществом сам по себе. Если студент использует еще не изученные Stream API, reflection, Lombok, многопоточность или внешний framework, он должен объяснить необходимость каждой такой конструкции. Непонимаемый код заменяется более простым.

## Технические требования

- Основная версия — Java 25 LTS.
- Сборка запускается Maven Wrapper; настраивать Maven с нуля студенту не требуется.
- JUnit используется с первой лабораторной.
- Обязательный CI отсутствует.
- Каталоги `target`, настройки IDE и секреты не добавляются в Git.
- Идентификаторы пишутся на английском без транслитерации.
- Метод возвращает результат, если его назначение не связано непосредственно с выводом.
- Студент добавляет тесты к обязательному поведению.
- Изменения одной лабораторной не должны затрагивать каталоги других работ без обоснования.

## Оценивание

| Компонент | Доля |
|---|---:|
| Функциональные требования | 35% |
| Автоматические тесты | 20% |
| Проектирование и читаемость | 15% |
| Git, ветка и pull request | 10% |
| Защита и изменение кода | 20% |

Непроходящая локальная сборка означает, что работа не готова к проверке. Неспособность объяснить или изменить собственное решение ограничивает оценку независимо от числа выполненных тестов.

Официальные баллы хранятся в ЭИОС или ведомости. GitHub используется как источник кода, истории изменений и комментариев, но не как единственная система учета оценок.

# Лабораторная работа 6. Коллекции и введение в дженерики

## Цель работы

Научиться выбирать стандартную коллекцию и создавать простой параметризованный класс без raw types и ручных приведений.

## Стартовые файлы

До начала работы преподаватель выдает каркас модуля `lab06`. Если каталога `lab06` нет или команда `./mvnw -pl lab06 test` сообщает, что модуль не найден, обратитесь к преподавателю и не изменяйте корневой `pom.xml` наугад.

## Что нужно знать до начала

- назначение `List`, `Set` и `Map`;
- базовая запись `List<String>`;
- итерация и `Comparator`;
- контракты `equals` и `hashCode`.

## Языковой бюджет

Впервые обязательны параметр типа `T` и стандартные generic-коллекции. Wildcards и PECS относятся к дополнительной части. Stream API пока не требуется.

## Справка

Дженерик позволяет компилятору проверить тип элементов. `List<String>` не принимает `Integer`, а `Stack<ProjectTask>` возвращает `ProjectTask` без ручного приведения.

Для стека в прикладном коде обычно следует использовать `ArrayDeque`, но самостоятельная реализация помогает понять контракт структуры данных.

## Подготовительная часть — выполнить дома

В модуле `lab06` создайте `Box<T>` с полем типа `T`, конструктором, `get` и `set`. Напишите тесты для `Box<String>` и `Box<Integer>`. В комментарии к тесту приведите одну некомпилируемую строку, например передачу `int` в `Box<String>`, но не оставляйте ее активным кодом. В описании PR одним предложением объясните, какую ошибку предотвращает параметр типа. Включите подготовительную часть в ветку `lab/06-generics`.

## Обязательное задание. Часть 1

Реализуйте:

```java
public final class Stack<T> {
    public void push(T value);
    public T pop();
    public T peek();
    public int size();
    public boolean isEmpty();
}
```

Можно использовать `ArrayList<T>` как внутреннее хранилище. `null` запрещен. `pop` и `peek` пустого стека выбрасывают `NoSuchElementException`.

## Обязательное задание. Часть 2

На основе данных предыдущих работ сформируйте аналитику обычными коллекциями и циклами.

### Программная инженерия

- число задач по статусам через `Map`;
- уникальные категории через `Set`;
- новый список задач, отсортированный по трудоемкости и идентификатору.

### Инженерия систем искусственного интеллекта

- число наблюдений по статусам через `Map`;
- уникальные источники через `Set`;
- новый список наблюдений, отсортированный по числу признаков и идентификатору.

Исходный список изменять нельзя. Для сортировки используйте `Comparator`, а не вычитание чисел.

## Пошаговый план

1. Завершите `Box<T>`.
2. Реализуйте пустой `Stack<T>` и тест `isEmpty`.
3. Реализуйте `push`, затем `peek`, затем `pop` с тестами после каждого шага.
4. Выберите коллекции для аналитики и запишите обоснование в README.
5. Реализуйте группировку, уникальность и сортировку циклами.

## Дополнительная часть

Выберите одно:

- реализуйте `Repository<ID,T>` на основе `LinkedHashMap`;
- реализуйте `copyAll(Collection<? extends T>, Collection<? super T>)` и объясните PECS;
- сравните учебный стек с `ArrayDeque<T>`.

- выбор коллекций соответствует требованиям порядка и уникальности;

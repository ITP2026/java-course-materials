# Лабораторная работа 5. Файлы, исключения и валидация

## Цель работы

Научиться читать текстовый файл в явной кодировке, преобразовывать строки в объекты и различать ошибку источника от ошибки отдельной записи.

## Стартовые файлы

До начала работы преподаватель выдает каркас модуля `lab05`. Если каталога `lab05` нет или команда `./mvnw -pl lab05 test` сообщает, что модуль не найден, обратитесь к преподавателю и не изменяйте корневой `pom.xml` наугад.

## Что нужно знать до начала

- `String` и его основные методы;
- checked и unchecked exceptions;
- `Path`, `Files`, UTF-8;
- базовый синтаксис try-with-resources.

## Языковой бюджет

Используйте конкретный профильный loader, обычные классы, список и исключения. Generic loader, полноценный CSV, reflection и Stream API не требуются.

## Справка

Ошибка источника не позволяет начать обработку: файл отсутствует или недоступен. Ошибка записи относится к одной строке: неверное число, пустое поле или неизвестный статус. Если возможно, корректные строки нужно сохранить, а ошибки — вернуть отдельным списком.

При оборачивании I/O-исключения сохраняйте исходную причину:

```java
throw new DataLoadingException("Cannot read " + path, cause);
```

## Формат файла

Используется упрощенный формат с разделителем `;`. Символ `;` внутри поля запрещен.

Программная инженерия:

```text
id;title;category;estimatedHours;status
T-101;Prepare release;backend;8;READY
```

Инженерия систем искусственного интеллекта:

```text
id;label;source;featureCount;status
S-101;cat;camera-1;128;READY
```

## Подготовительная часть — выполнить дома

В тесте с `@TempDir` самостоятельно создайте UTF-8-файл с тремя строками: `10`, `bad`, `20`:

```java
@TempDir
Path tempDir;

Path file = tempDir.resolve("numbers.txt");
Files.write(file, List.of("10", "bad", "20"), StandardCharsets.UTF_8);
```

Аннотация импортируется из `org.junit.jupiter.api.io.TempDir`. Прочитайте файл через `Files.readAllLines` и проверьте содержимое. Затем преобразуйте строки в целые числа обычным циклом и отдельным тестом проверьте, что строка `bad` приводит к `NumberFormatException`. Не используйте Stream API. Тестовый файл создается во временном каталоге и не добавляется в Git. Включите подготовительную часть в ветку `lab/05-files`.

## Обязательное задание

Создайте:

```java
public final class ValidationError {
    // lineNumber, field, message
}

public final class LoadResult {
    // список корректных профильных объектов и список ошибок
}

public final class DataLoadingException extends RuntimeException {
    public DataLoadingException(String message, Throwable cause) {
        super(message, cause);
    }
}
```

Также создайте конкретный `TaskFileLoader` или `SampleFileLoader` с методом `load(Path path)`.

### Контракт

1. Файл читается как UTF-8.
2. Заголовок проверяется отдельно.
3. Каждая непустая строка должна иметь ожидаемое число полей.
4. Ошибка записи добавляется в список с номером строки и не останавливает чтение остальных записей.
5. Отсутствующий или недоступный файл приводит к `DataLoadingException` с сохраненным `cause`.
6. Loader ничего не печатает и не вызывает `printStackTrace`.
7. Проверка предметных ограничений выполняется до добавления объекта в результат.

## Пошаговый план

1. Создайте тестовый файл в `@TempDir`.
2. Реализуйте чтение и проверку заголовка.
3. Реализуйте parsing одной корректной строки.
4. Добавьте обработку неправильного числа, enum и числа полей.
5. Проверьте совместную обработку корректных и ошибочных строк.
6. Реализуйте ошибку источника с сохранением причины.

## Обязательные тесты

- корректный файл;
- кириллица или другой Unicode-текст;
- пустое поле;
- неправильное число;
- неизвестный статус;
- неправильное число столбцов;
- корректные и ошибочные строки вместе;
- отсутствующий файл.

## Дополнительная часть

Поддержите поля в двойных кавычках и разделитель внутри них. Не используйте один regex для разбора всей строки. Альтернатива — вынести общий `RowParser<T>` после изучения дженериков.

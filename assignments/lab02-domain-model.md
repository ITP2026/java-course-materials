# Лабораторная работа 2. Классы и инкапсуляция

## Цель работы

Научиться описывать собственный тип данных, проверять состояние в конструкторе и размещать поведение рядом с данными.

## Стартовые файлы

В первоначальном template repository подготовлен только модуль `lab01`. До начала этой работы преподаватель выдает каркас модуля `lab02`. Если каталога `lab02` нет или команда `./mvnw -pl lab02 test` сообщает, что модуль не найден, обратитесь к преподавателю и не изменяйте корневой `pom.xml` наугад.

## Что нужно знать до начала

- классы, поля, конструкторы и методы;
- `private`, `public`, `final`, `this`;
- простые JUnit-тесты.

## Языковой бюджет

Используйте обычные классы, enum, конструкторы и методы. Дженерики, наследование, Stream API, Lombok и reflection не требуются.

## Справка

Инвариант — условие, которое остается истинным для любого корректно созданного объекта. Конструктор не должен создавать объект с пустым идентификатором или недопустимым числовым значением.

Инкапсуляция означает не механическое наличие getters и setters, а защиту состояния через небольшой осмысленный публичный API.

## Подготовительная часть — выполнить дома

В модуле `lab02` создайте учебный класс `BankAccount`:

- приватное поле `int balance`;
- конструктор, запрещающий отрицательный начальный баланс;
- метод `deposit(int amount)`, принимающий только положительную сумму;
- метод `withdraw(int amount)`, запрещающий неположительную сумму и превышение остатка;
- метод `getBalance()` без setter.

Добавьте тест успешного списания и тест, проверяющий исключение при превышении остатка. Подготовительный класс, его тесты и обязательное задание включаются в одну ветку `lab/02-classes` и один PR.

## Обязательное задание

Выберите вариант своего направления.

### Программная инженерия

Создайте `ProjectTask`:

- `String id`;
- `String title`;
- `TaskStatus status`;
- `int estimatedHours`.

Операции:

- создать задачу;
- изменить статус через `changeStatus`;
- определить, завершена ли задача;
- увеличить оценку трудоемкости на положительное число часов.

### Инженерия систем искусственного интеллекта

Создайте `DataSample`:

- `String id`;
- `String label`;
- `SampleStatus status`;
- `double[] features`.

Операции:

- создать наблюдение;
- изменить статус через `changeStatus`;
- определить, готово ли наблюдение;
- вычислить среднее значение признаков.

### Общий контракт

1. Идентификатор и текстовые обязательные поля не равны `null` и не пусты.
2. Числовые значения соответствуют смысловым ограничениям.
3. Поля закрыты; setter для каждого поля создавать нельзя.
4. Статус меняется только специальным методом.
5. В варианте ИИ массив копируется в конструкторе и при возврате из accessor.
6. Модель ничего не читает из консоли и ничего не печатает.

## Пошаговый план

1. Запишите инварианты в README лабораторной.
2. Создайте enum статусов.
3. Реализуйте конструктор с проверками.
4. Добавьте поведенческие методы.
5. Напишите тест корректного объекта и отдельные тесты каждого ограничения.
6. Проверьте невозможность неконтролируемого изменения состояния.

## Дополнительная часть

Создайте неизменяемый класс идентификатора либо record и объясните, почему он представляет значение. Для варианта ИИ добавьте нормализацию признаков без изменения исходного объекта.

## Критерии приемки

- `./mvnw -pl lab02 test` завершается успешно;
- конструктор поддерживает инварианты;
- класс содержит поведение, а не только поля и accessors;
- нет универсального `setId` или `setEstimatedHours`;
- создан PR из `lab/02-classes` в `main`.

# Лабораторная работа 3. Интерфейсы и полиморфизм

## Цель работы

Научиться задавать общий контракт интерфейсом и заменять одну реализацию другой без изменения использующего ее класса.

## Стартовые файлы

До начала работы преподаватель выдает каркас модуля `lab03`. Если каталога `lab03` нет или команда `./mvnw -pl lab03 test` сообщает, что модуль не найден, обратитесь к преподавателю и не изменяйте корневой `pom.xml` наугад.

## Что нужно знать до начала

- классы и объекты;
- интерфейсы и `implements`;
- переопределение и `@Override`;
- тип ссылки и фактический тип объекта.

## Языковой бюджет

Используйте обычный интерфейс, два реализующих класса и композицию. Дженерики, reflection, Stream API и сложные иерархии не требуются.

## Справка

Тип ссылки определяет доступные операции при компиляции. Фактический тип объекта определяет вызываемую переопределенную реализацию. Клиенту следует зависеть от интерфейса, если конкретное поведение должно быть заменяемым.

## Подготовительная часть — выполнить дома

В модуле `lab03` создайте:

```java
public interface DiscountPolicy {
    double apply(double price);
}
```

Реализуйте `NoDiscount` и `PercentDiscount`. `NoDiscount` возвращает исходную цену. Процент передается в конструктор `PercentDiscount`, должен находиться в диапазоне от 0 до 100, а скидка 20% для цены 100 должна дать результат 80. Отрицательная цена запрещена. Создайте `PriceCalculator`, который получает `DiscountPolicy` через конструктор и не создает конкретную политику внутри себя. Добавьте по одному тесту для каждой реализации и тест замены политики. Включите подготовительную часть в ветку `lab/03-polymorphism`.

## Обязательное задание

### Программная инженерия

```java
public interface PriorityPolicy {
    int calculatePriority(ProjectTask task);
}
```

Реализуйте:

- `EffortPriorityPolicy`;
- `StatusPriorityPolicy`.

Создайте `TaskPrioritizer`, принимающий `PriorityPolicy` через конструктор и выбирающий более приоритетную из двух задач.

### Инженерия систем искусственного интеллекта

```java
public interface NormalizationStrategy {
    double[] normalize(double[] values);
}
```

Реализуйте:

- `MinMaxNormalization`;
- `MeanCenteringNormalization`.

Создайте `FeatureProcessor`, принимающий `NormalizationStrategy` через конструктор и обрабатывающий один вектор.

### Общий контракт

1. Использующий класс хранит поле интерфейсного типа.
2. Реализация передается через конструктор и не создается внутри обработчика.
3. Для выбора поведения запрещены `instanceof`, имя класса и цепочка `if` по типу.
4. Входные объекты и массивы не изменяются.
5. Для каждой реализации есть минимум два теста.

## Пошаговый план

1. Реализуйте интерфейс.
2. Реализуйте первую стратегию и тесты.
3. Подключите ее к обработчику.
4. Реализуйте вторую стратегию без изменения обработчика.
5. Добавьте тест, показывающий заменяемость реализаций.

## Дополнительная часть

Добавьте третью стратегию. Для программной инженерии это может быть политика с учетом срока; для ИИ — z-score normalization. Составную стратегию реализуйте только после обсуждения с преподавателем.

## Критерии приемки

- `./mvnw -pl lab03 test` завершается успешно;
- клиент зависит от интерфейса;
- есть ровно необходимая, а не искусственная иерархия;
- новая реализация не требует изменения обработчика;
- создан PR из `lab/03-polymorphism` в `main`.
